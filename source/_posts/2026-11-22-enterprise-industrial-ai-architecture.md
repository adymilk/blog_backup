把大模型接入企业级工业软件时，研发团队最先遇到的挑战往往不是模型不够聪明，而是**“严谨的工业逻辑”与“概率性的文本生成”之间的冲突**。例如，在质量工程场景中，一次错误的 CPK 计算或漏报一个 SPC 判异点，就可能导致整批产品风险误判。

<!--more-->

## 核心架构原则：计算确定性，推理智能化

在设计工业数据分析与质量智能应用时，最稳妥的工程架构是将**“意图编排与知识检索”**交给 AI Agent，而把**“数据提取与统计运算”**严格收口到确定性的代码与工业引擎中：

```text
[用户自然语言提问]
        │
        ▼
[AI Agent 编排层] ◀────▶ [RAG 企业知识库：SOP / 历史异常复盘 / 质量标准]
        │
        ├──▶ [ETL / 数据查询工具：按时间、产线、工序提取清洗后数据]
        ├──▶ [MCP Statistical Tool：调用 SPC / MSA / 过程能力计算引擎]
        └──▶ [结构化结果 + 可解释结论输出]
```

## 关键组件分工与工程落地要点

### 1. 用 MCP（Model Context Protocol）标准化工业工具接口

过去每接入一个大模型应用，都要针对不同模型重写一套 Function Calling 适配层。通过 **MCP Server** 将企业既有的统计分析能力（如生成控制图、计算过程能力指数、触发 ETL 任务）暴露为标准化的 Tool：

- **强类型参数约束**：使用 JSON Schema 明确定义分析类型、子组大小（Subgroup Size）、置信区间等参数，减少模型传参错误。
- **权限与审计隔离**：Agent 只能通过受控工具访问脱敏后的分析视图，不直接暴露底层生产库连接串。

### 2. 用 RAG 消除行业术语与企业私有规范的盲区

通用大模型并不了解某家工厂内部的缺陷代码定义、客户特殊质量协议或特定设备的历史维修策略。RAG 管道需要重点优化两件事：

- **结构化切分与元数据过滤**：质量文档往往包含大量表格与流程图，按章节标题与文档类型（如 `产线/工序/生效日期`）建立元数据索引，比单纯按固定 Token 切分准确率高得多。
- **引用溯源（Citation）**：每一条排查建议必须附带原 SOP 文档出处，方便一线工程师复核。

### 3. 用 Golden Set 评测体系守住上线底线

很多企业 AI 项目停留在 Demo 阶段，核心原因是**缺少客观的回归评测机制**——每次微调 Prompt 或更换模型，团队只能靠“人工试几句”来凭感觉评估。

建议在项目早期就同步构建 **Golden Set（黄金评测集）**：

- 收集 30–50 条真实业务高频问题（覆盖正常查询、参数缺失澄清、边界异常数据）。
- 明确评估三个指标：**意图与参数提取准确率**、**工具调用成功率**、**结论与标准答案的一致性**。
- 将评测脚本纳入 CI/CD，任何 Prompt 或检索策略修改都必须跑通回归基线后才能发布。

## 结语

企业级 AI 工程的成熟度，不取决于用了多少前沿概念，而取决于**边界划得有多清、工具封装得有多稳、评测数据有多扎实**。
