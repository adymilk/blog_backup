## 1. 项目背景

在制造业质量工程与过程控制场景中，Minitab 是行业广泛使用的统计分析工具。随着企业数字化转型，业务团队希望将原本依赖单机桌面操作的 SPC（统计过程控制）、过程能力分析等能力集成到统一的 Web 质量管理平台中。

- **所属领域**：工业软件集成 / 质量数据分析平台
- **客户与团队规模**：[可编辑占位：例如 某制造企业质量管理部门]

## 2. 业务痛点

- **接口架构限制**：Minitab 仅开放面向 Windows 桌面的 C# COM 组件接口，无法被 Linux/Web 服务端直接调用。
- **分析效率瓶颈**：工程师需要人工导出数据、手动配置子组大小与判异规则，再截图回传报告，耗时且易出错。
- **并发与稳定性风险**：桌面进程直接暴露给 Web 请求容易出现进程阻塞、超时或状态丢失。

## 3. 解决方案

设计并实现「Web 业务层 + 异步任务队列 + Windows 常驻 COM 桥接服务」的解耦架构：

- 将统计分析请求抽象为带唯一 `OrderID` 的异步分析任务，前端与业务系统通过任务 ID 解耦。
- 在 Windows 节点部署开机自启的常驻桥接服务，持续轮询待处理任务并调用本地 Minitab COM 组件完成计算与图表生成。

## 4. 系统架构

```text
[Web 质量平台 / 业务前端]
        │  1. 提交分析参数（分析类型、子组大小、判异规则）+ OrderID
        ▼
[业务 API & 任务状态数据库]
        │  2. Windows 常驻服务轮询待执行任务
        ▼
[C# COM 桥接服务 (Windows Service)]
        │  3. 调用本地 Minitab COM 组件执行计算并生成图表/结论
        ▼
[结果存储与前端轮询回显]
```

## 5. 核心功能

- **多参数动态分析**：支持按业务请求动态传入分析类型、子组大小、判异原则等变量。
- **任务状态机管理**：基于 `OrderID` 追踪任务排队、执行中、完成与异常状态。
- **图表与文字说明自动输出**：自动生成控制图图像及对应的统计判异说明，回传至 Web 端展示。

## 7. 经验总结

- **在约束中做架构取舍**：相比从零重写全套统计与判异算法（难以保证与 Minitab 完全一致），COM 桥接是在工业合规与交付周期下的最优工程解。
- **生产可靠性意识**：工业现场服务不仅要“跑得通”，更需要完善的异常重试、进程守护、日志可观测与告警机制。
